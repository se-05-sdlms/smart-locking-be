# Locker connectivity

The backend subscribes to `lockers/{device}/heartbeat` and `lockers/{device}/status`. A heartbeat or `online` status marks the locker online. A `status` payload of `offline` marks it offline immediately; firmware should configure that message as its MQTT Last Will. Live door status messages also refresh `LastSeenAt`; retained door messages are ignored because they do not prove the device is currently connected.

`LockerMonitoring:Enabled` defaults to `false` while the current firmware does not send a heartbeat or Last Will. With monitoring disabled, stale lockers are not marked offline and connection status does not block unlocks. Enable it only after deploying firmware that sends a periodic heartbeat and an offline Last Will; restart the backend after changing this setting. Set `LockerMonitoring:OfflineAfterSeconds` above the heartbeat interval (minimum 10 seconds; default 90). When enabled, the worker checks every 5 seconds and marks a locker offline after the cutoff. A newly registered locker uses the `Unknown` enum value until its first signal and becomes `Offline` after the cutoff.

On a connection change, the backend writes `LockerEvent.ConnectionChanged` and publishes `LockerConnectionChanged` through OperationsHub. Offline transitions also create in-app notifications for assigned active operators, or active administrators if no operator is assigned. Remote unlocks return HTTP 409 with code `locker/offline` when connection status is not online.
