# Locker events and door alerts

The backend records `DoorChanged` when a compartment sensor changes, `OperationalStatusChanged` when a locker or compartment is changed through the API, and `DeviceAlert` when firmware publishes `lockers/{device}/alerts` with a nonempty alert message (up to 500 characters). Door status still accepts `OPEN` and `CLOSED` on `lockers/{device}/doors/{channel}/status`. Firmware may also send JSON such as `{"status":"OPEN","occurredAt":"2026-10-21T06:00:00Z"}`; the timestamp lets the backend reject duplicate and delayed readings. Plain status messages can be deduplicated by current state, but need a device timestamp to detect out-of-order changes.

Set `LockerMonitoring:DoorOpenAlertAfterSeconds` (minimum 10, default 120). The worker checks every 5 seconds. If the latest door event is still Open past the threshold, it creates one `DoorOpenTooLong` incident for that opening cycle, linked to the latest nearby delivery, pickup or return access where available. The incident appears in operational records. The worker also writes a `DeviceAlert`, sends an in-app notification to the assigned operator (or administrators) and publishes an OperationsHub event.
