# Incident SLA policy (#153)

The existing SLA worker and priority mapping are retained. Administrator policy create/update accepts an optional `incidentSla` object containing eight minute values: `criticalAcknowledgeMinutes`, `criticalResolveMinutes`, `highAcknowledgeMinutes`, `highResolveMinutes`, `mediumAcknowledgeMinutes`, `mediumResolveMinutes`, `lowAcknowledgeMinutes`, `lowResolveMinutes`. Policy responses include the same object. Omitted settings default to 15/60, 30/240, 120/1440 and 480/4320 respectively. Values must be positive and resolution must be at least acknowledgement; API validation and DB constraints enforce this.

Only a draft policy can be edited. Administrator creates a new version and activates it through existing System Policy APIs to change live targets. On each worker run the currently effective active policy supplies targets. They apply to unresolved incidents using their original `CreatedAt`, so shortening a target can cause immediate escalation; extending it does not undo an earlier warning or escalation. No lifecycle timestamps or notification markers are reset. Warning percentage, polling interval and worker enablement remain deployment settings. If no effective policy exists, existing `IncidentSla` deployment defaults are used.

The additive migration fills existing policy rows with the documented default targets. It does not apply itself to a database or modify incident records. FE System Policy forms are owned separately and must send/retain this optional object when editing a draft with custom targets. Operator replacement fields from #195 are separate and must be combined during integration.
